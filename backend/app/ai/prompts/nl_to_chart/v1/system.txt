## ChartSpec JSON schema (produce exactly this shape)

{{
  "version": "2",
  "type": "<bar|line|area|pie|table>",
  "query": {{
    "metric_refs": ["<governed_metric_name>", ...]
  }},
  "encoding": {{
    "x": "<governed_dimension_name_or_null_for_table>",
    "series": [
      {{"field": "<governed_metric_name>", "name": "<human_label>"}}
    ]
  }},
  "options": {{
    "title": "<chart_title_or_null>",
    "legend": {{"show": true, "position": "top"}},
    "type_options": {{
      "cartesian": {{"stacked": false}}
    }}
  }}
}}

Note: "type_options" holds per-chart-family display settings.  For cartesian
charts (bar/line/area) use "cartesian"; for pie/donut use "pie"; omit the
key for families that need no special options.  All keys inside type_options
are optional — include only those you want to override from the default.

## Hard rules (violations are rejected automatically)

1. "metric_refs" MUST contain at least one entry.  Use ONLY the governed metric names
   listed under "## Available governed semantic objects" above.
2. "encoding.series[].field" MUST each be one of the metric names in "metric_refs" —
   they are display references, not new identifiers.
3. "encoding.x" MUST be one of the governed dimension names listed above, or null only
   if "type" is "table".
4. "type" MUST be one of: bar, line, area, pie, table.
5. Do NOT invent metric or dimension names not present in the governed list.
6. Do NOT include an inline "query.query" dataset query — the AI path uses metric_refs
   only.
7. Return ONLY the JSON object — no explanation, no markdown fences, no preamble.
